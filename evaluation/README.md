# Automated Evaluation Framework

This evaluation framework tests the Adaptive Multimodal HRI Framework components end-to-end, based on realistic scenarios using the actual project components (Voice, Vision, Gesture, Memory, Coordinator, Planner, Safety, Controller).

## Running the Evaluation

To run the evaluation:

```bash
python3 evaluation/run_evaluation.py
```

Results are saved to `evaluation/results/`.

---

## Recommended DA2 Results Section

The following structure is recommended for Section 4 (Results and Evaluation Metrics) of your DA2 report.

### 4.1 Experimental Setup
*   **Description**: Explain that the system is evaluated using a scenario-based testing framework covering 21 hand-crafted multimodal HRI cases. The framework executes the actual LangGraph orchestration pipeline, activating each agent.
*   **Limitation Note**: Explicitly state that certain ML benchmark metrics (e.g., WER for voice, mAP/IoU for object detection) require large-scale ground-truth annotated datasets, which are left for future work. The current evaluation focuses on system-level integration and decision accuracy.

### 4.2 Voice and Gesture Evaluation
*   **Metric to Report**: Intent Extraction Accuracy (Voice) and Gesture Recognition Accuracy (Scenario-based).
*   **Data to Use**: Use the "Voice / Intent Evaluation" and "Gesture Evaluation" table outputs.
*   **Note**: State that gesture accuracy is based on correct classification and parsing in controlled scenarios, rather than the HaGRID benchmark checkpoint directly.

### 4.3 Vision/Object Detection Evaluation
*   **Note**: Mention that VisionAgent successfully parses YOLO bounding boxes and spatial sectors.
*   **Limitation**: "Object detection mAP/IoU evaluation was not performed because a suitable ground-truth bounding-box evaluation dataset specific to the robot's camera view is not currently available. Creating this dataset is proposed as future work."

### 4.4 Multimodal Fusion Evaluation
*   **Metric to Report**: VALID Decision Precision, Conflict Detection Precision, Target Not Found Precision, Ambiguity Detection Precision.
*   **Data to Use**: Use the "Multimodal Fusion" table. This highlights the system's ability to cross-correlate pointing gestures with detected objects and voice targets.

### 4.5 Memory and Context Evaluation
*   **Metric to Report**: Pronoun Resolution and Context Grounding Accuracy.
*   **Data to Use**: Reference the multi-turn test cases (e.g., T12 and T13) where referential targets like "it" are successfully mapped to prior objects in memory.

### 4.6 Safety Evaluation
*   **Metric to Report**: Safety Decision Accuracy, Unsafe Actions Blocked.
*   **Data to Use**: Use the "Safety Evaluation" table. Highlight how the system correctly identifies unsafe states (e.g., human too close) and overrides standard commands.

### 4.7 End-to-End System Performance
*   **Metric to Report**: Mean, Median, Min, Max End-to-End Latency.
*   **Data to Use**: Use the "System Performance" table generated by the script, demonstrating real-time or near real-time orchestration latency.

### 4.8 Discussion
*   Provide a brief synthesis of the results, discussing where the multimodal fusion resolved ambiguity, how the safety agent acted as a successful fail-safe, and outlining dataset collection as the primary avenue for future work.
